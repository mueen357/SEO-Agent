# Phase 3 — Task 3.2: Technology & CMS Detection Dashboard Architecture

## 1. Executive Summary

Phase 3 — Task 3.2 implements the production **Technology & CMS Detection Dashboard** for the AI-Powered Website Audit Chrome Extension. The dashboard provides an interactive, dark navy / cyan themed interface embedded into the Chrome extension sidepanel (`extension/entrypoints/sidepanel/App.tsx`), consuming deterministic, evidence-based fingerprinting results generated by the FastAPI backend (`backend/app/technology/`).

The component (`extension/components/audit/TechnologyDashboard.tsx`) provides complete visibility into detected Content Management Systems, frontend frameworks, backend runtimes, WordPress themes, and observable WordPress plugins, backed by an accessible, secure Evidence Inspector that never renders untrusted HTML.

---

## 2. Core Architectural Principles

1. **Deterministic Passive Display:** The dashboard visualizes evidence-backed detections without fabricating technologies or guessing versions.
2. **Coexistence Presentation:** Multi-layer technology stacks (e.g., WordPress + PHP, Next.js + React + Node.js) are presented simultaneously rather than forcing a single winner.
3. **Conservative Version Provenance:** Query string parameters (e.g. `?ver=1.2`) are labeled as unverified asset hints (`Asset hint: v1.2 (Unverified release)`). If absent, findings display `Version not verified`.
4. **Zero-Injection Security:** All untrusted strings from crawled pages are strictly rendered as standard text nodes. The dashboard uses zero instances of `dangerouslySetInnerHTML`. Sensitive cookies, authentication headers, and passwords are never displayed.
5. **Robust State Machine:** The UI distinguishes 10 states gracefully, treating unanalyzed audits (HTTP 404 from summary) as an actionable prompt to run detection rather than a fatal application crash.

## 4. Section Breakdown & Behavior

### Section A: Technology Overview
Displays high-level diagnostic cards:
- **Primary CMS:** Shows the primary detected CMS or `None / Unknown`. Unknown is never labeled as "Custom" without affirmative proof.
- **Technologies Count:** Displays total technologies, with explicit `detected` vs `possible` count badges.
- **Confidence Distribution:** Displays counts in High ($\ge 85\%$), Medium ($50-84\%$), and Low ($< 50\%$) bands with threshold disclosure ($\ge 70\%$ required for `detected`).
- **WP Components:** Summarizes observed theme and plugin counts with instant status hint.

### Section B: CMS & Site Builders
Presents evidence-backed findings for platforms including WordPress, Shopify, Wix, Webflow, and Squarespace. Each card details detection method, confidence tier, and affected page volume.

### Section C: Frontend Frameworks
Accurately displays coexisting frontend libraries (e.g., React alongside Next.js, or Vue alongside Nuxt). Both parent and child frameworks are preserved with their respective detection evidence.

### Section D: Backend Runtimes & Frameworks
Visualizes server runtimes (PHP, Node.js, Laravel, Django). Inferred runtimes (e.g., PHP implied by WordPress) are explicitly marked with `detection_method: inferred` and clear explanatory summaries.

### Section E: WordPress Themes
- Differentiates **Active Theme** (observed in body classes, main stylesheet link rel) from **Referenced Theme** (assets located in `/wp-content/themes/{slug}/`).
- Query parameter versions are labeled: `Asset hint: v{version} (Unverified release)`.
- If no version hint is observed, displays `Version not verified`.

### Section F: WordPress Plugins
- Lists observed public plugins discovered through asset paths (`/wp-content/plugins/{slug}/`) and HTML comments.
- Displays explicit detection boundary disclaimer:
  > **Detection Boundary:** Only publicly observable frontend asset paths and HTML comments are reported. Server-side, headless, or admin-only WordPress plugins do not emit public markers and cannot be discovered without intrusive probing.

## 5. Evidence Inspector

Each finding card features an accessible disclosure trigger (`role="button"`, `tabIndex={0}`, with keyboard handlers for `Enter` and `Space`):
- **Safety:** Strings are bound and escaped through standard React JSX expressions.
- **Bounded Strings:** Monospace containers employ `break-all` and `max-h-48` scrolling to prevent layout overflows.
- **Sensitive Data Exclusion:** Crawler and extractors exclude raw cookie values, session tokens, passwords, and authorization headers. Only safe cookie names (`HeaderTechnologyExtractor.KNOWN_COOKIE_NAMES`) are referenced as existence signals.

## 6. Authoritative Confidence & Status Tiers

Reconciling documentation with authoritative backend code (`backend/app/technology/classifiers/base.py`, `TechnologyDetector`):

| Metric | Range | Status / Level | Representation |
|---|---|---|---|
| **Status** | $\ge 0.70$ | `detected` | Emerald badge with CheckCircle2 icon |
| **Status** | $0.40 \le \text{conf} < 0.70$ | `possible` | Amber badge with HelpCircle icon |
| **Status** | $< 0.40$ | `unknown` | Slate badge |
| **Confidence Level** | $\ge 0.85$ | `high` | Emerald badge (`{pct}% (high)`) |
| **Confidence Level** | $0.50 \le \text{conf} < 0.85$ | `medium` | Cyan badge (`{pct}% (medium)`) |
| **Confidence Level** | $< 0.50$ | `low` | Amber badge (`{pct}% (low)`) |

## 7. UI State Handling (10 Distinct States)

| State | Trigger Condition | UI Behavior |
|---|---|---|
| **NO AUDIT SELECTED** | `auditId === null` | Explanatory banner prompting selection or crawl initiation |
| **BACKEND OFFLINE** | `!isBackendOnline` | Red connection warning with backend host guidance (`127.0.0.1:8000`) |
| **AUDIT RUNNING** | `isAuditRunning === true` | Spinner with crawl notification; prevents premature execution |
| **INSUFFICIENT EVIDENCE** | 0 pages crawled in audit | Amber limitation banner noting HTML/header evidence requirement |
| **NOT ANALYZED** | HTTP 404 from `/technologies/summary` | Actionable prompt with "Run Technology Analysis" trigger (non-fatal) |
| **LOADING DATA** | Fetching summary or findings list | Centered cyan loading spinner with descriptive status |
| **ANALYSIS IN PROGRESS** | POST `/technologies/analyze` active | Re-analyze button shows spinning icon with disabled state |
| **EMPTY / NO TECH DETECTED** | 0 technologies detected | Info card explaining no known CMS or framework signatures matched |
| **SUCCESS** | Detections loaded | Complete overview, tabs, filters, and paginated finding cards |
| **API ERROR** | Network or server failure | Dismissible error banner with retry action |
